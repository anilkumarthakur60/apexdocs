VERDICT:
SPINE: Proposal 1 (mobile-first). Its core thesis is the only one that is provably correct without JS: `#axui-panel` stays in fixed DOM order (nav → doc → panel) and is *promoted* into a right rail by CSS grid placement at wide widths. `display:none` is never applied to it at any width. That single decision fixes the worst defect in the UI (code samples, try-it-out, response viewer, history and the schema JSON dump vanish below 1100px), and it fixes it in a way that also gives tab order, Ctrl+F, screen-reader reading order and print for free. Proposal 3 reaches the same goal by reparenting the node with JS on matchMedia changes; Proposal 2 by turning it into a bottom sheet. Both make layout correctness depend on JS running correctly, and both introduce a second container/state path for `renderPanel`. Rejected. The governing principle for the whole rebuild is therefore: **DOM order is fixed and semantic; CSS alone decides presentation; no JS ever moves a node.** That also means the mobile nav drawer is a CSS overlay of the same grid child (`visibility:hidden` + `inert`), not Proposal 3's `<dialog>` reparenting.

GRAFTED FROM PROPOSAL 3 (craft) — the substrate, and it beats the spine on two points:
1. `body{display:grid;grid-template-rows:auto auto 1fr;height:100dvh}` replaces all pixel arithmetic. This is strictly better than Proposal 1's `--top-h` ResizeObserver: a grid row cannot desync from its content, so the wrapping banner, the dismiss-banner dead strip, the `--bar-h` duplication and the mobile-Safari clipped footer all die with zero JS. **`--top-h` and the ResizeObserver are dropped entirely.** The two things Proposal 1 needed `--top-h` for are solved structurally instead: the drawer is a grid child (no `top:` offset to compute) and the env popover gets a `position:relative` wrapper around its trigger.
2. Native platform widgets instead of hand-rolled ones: `<details>/<summary>` for the response accordion, schema expanders, history and the JSON dump (focusable, Enter/Space, implicit `aria-expanded`, auto-expanded by Chrome find-in-page — replaces a 16×16 button whose entire accessible name is "▶"); `<dialog>`+`showModal()` for the palette and shortcuts only (free focus trap, inert background, `::backdrop`, Escape); a `--ring` token plus one global `:focus-visible` rule replacing six `outline:none` declarations; three live regions with distinct jobs; intent-based `prefers-reduced-motion` instead of the `*{...!important}` nuke; `forced-colors` support; `@media print` with `beforeprint` expansion; `AbortController` + layout-matched skeletons; the `statusClass` fix; real `<h1>`/`<section>`/heading hierarchy.

GRAFTED FROM PROPOSAL 2 (information-density) — the state layer, which Proposal 1 only half-commits to:
1. Build the nav tree **once**, then only patch it (`applyNavState` moves `aria-current`; `filterNav` toggles `hidden`), with per-tag collapse persisted to `lsSetJson('nav.open')` and group order/labels from `spec.tags` / `x-tagGroups` / `x-displayName`. Proposal 1 proposes debounce + patch but keeps re-rendering as a path; Proposal 2's "one builder, two mutators, nothing else touches nav DOM" rule is the version that actually holds.
2. One weighted `buildSearchIndex(spec)` feeding **both** the ⌘K palette and the sidebar filter (the palette's placeholder already promises schemas it does not index; the filter hides webhooks the moment you type).
3. The structural schema→operations reverse index (today "Used by" is a `JSON.stringify().indexOf()` substring test, so `User` matches every op touching `UserProfile`).
4. `#ax-ctx`: a sticky operation-context bar (method · truncated-from-the-left path · section jump chips · always-visible permalink). Cheap, no competitor ships it, and on narrow widths it is also where the "jump to Code / Try it" buttons live — so it doubles as Proposal 1's action bar without a second fixed element.
5. Response `headers` and `links` rendering (the package's own `#[ResponseHeader]` attribute is currently silently dropped by the UI), plus storage pruning and a "Clear stored data" control.

DELIBERATELY DEFERRED (agreeing with Proposal 1's judgement over 2 and 3): lazy/unbounded schema expansion with stable dotted keys, merged `allOf`, `discriminator` tabs, schema-derived examples, spec-driven `securitySchemes` auth, typed try-it inputs / multipart / cookies, tag landing pages, read mode, OAuth2 PKCE. These are content-quality gaps, not reachability or correctness gaps, and each is far safer to land on a settled DOM, a delegated event layer and a patch-based nav. `renderSchema` in this pass gets markup + cycle-detection + resolution fixes only, so reviewers can diff the recursion logic to near zero.

ONE STRUCTURAL ADDITION NEITHER PROPOSAL MADE, AND IT IS WHAT MAKES THE WORKSTREAMS INDEPENDENT: `css()` and `js()` are each a single ~540/~1200-line heredoc. Split them in the first workstream into named part-methods concatenated in order — `cssShell/cssNav/cssDoc/cssSchema/cssPanel/cssResponsive` and `jsCore/jsChrome/jsNav/jsIndex/jsDoc/jsSchema/jsPanel/jsInit`. RISKS:
  - `position:sticky` on the promoted panel is fragile by construction: it requires `#axui-content` to be the scroll container and `#axui-panel-slot` to `align-self:stretch` with NO `overflow` of its own. A future rule setting `overflow` on the slot degrades it silently to static with no error. Mitigation: a comment block at the rule site plus two CSS regression tests (no `display:none` on `#axui-panel`, no `overflow` on `#axui-panel-slot`).
  - Two layout modes below/above 900px means `scrollIntoView` and `scrollTop` target different scrollers (`document.scrollingElement` vs `#axui-content`). Every scroll call must go through one `axScrollTo(el)` helper that picks the right container from a `matchMedia` flag; a direct `element.scrollIntoView()` left anywhere will misbehave in one mode.
  - `100dvh` reflows the pane row as mobile browser chrome shows and hides — a small visual settle. Accepted deliberately: the alternative (`100vh` + `overflow:hidden`) permanently amputates the last 60–115px of every page on the browsers most people read docs in.
  - Native `<dialog>`/`showModal()`, `:focus-visible`, `overflow:clip`, `100dvh` and `content-visibility` together set a real engine floor around Safari 15.4 / Chrome 111. That is a deliberate trade of legacy reach for ~120 lines of hand-written focus-trap and backdrop code that would otherwise be subtly wrong. Must be stated in the changelog.
  - `<details>`/`<summary>` conversion has two traps: `toggle` does not bubble (the delegated listener MUST use capture), and interactive/decorative children inside a `<summary>` swallow or hijack the click. Badges must be `pointer-events:none`; the permalink button must live outside the summary.
  - The `data-act` conversion is ~40 sites across five render paths. A single missed conversion is a silently dead button with no console error. Gate the workstream on a grep for `onclick` returning zero hits in the generated HTML, and add a UiRendererSafetyTest asserting that.
  - Renaming the try-it id prefixes (`axi-` → `axi-p-`/`axi-q-`/`axi-h-`) touches `paramFields`, `bulkGroup`, `bulkReadFields`, `bulkWriteFields`, `axSend` and `axHistRestore`. Any one left behind breaks parameter sending or history restore. Version history entries and ignore unversioned ones so stored data cannot half-restore.
  - Build-once nav introduces two code paths (builder + mutators) that must agree on row state. Enforce the invariant that all row state lives in `data-*` read by both, and that `applyNavState` is the only writer of `aria-current`/`.active`/`aria-expanded`. Drift here manifests as a wrong highlighted row, which is hard to spot in review.
  - Roving focus plus `hidden`-based filtering can leave focus on a hidden row. `filterNav` must move focus to the nearest visible row, and `j`/`k` must skip `[hidden]` and collapsed subtrees.
  - `content-visibility:auto` makes browser find-in-page skip content in skipped subtrees and can make `scrollIntoView({block:'nearest'})` land imprecisely. Applied at group granularity only, so a skipped subtree is always a collapsed or off-screen group; `moveNav` expands and scrolls the target group before focusing. The `beforeprint` expander must also force these open.
  - `pushState` per navigation changes user-visible behaviour: Back now steps through endpoints instead of leaving the docs. Correct, but people will notice. It also means Back must not re-announce or re-scroll jarringly — restore scroll from `history.state`.
  - The hash contract is the highest-consequence thing in this plan. `op_` and `schema_` must be byte-identical to today; the `wh_` change must keep accepting the legacy `_`-split form. A mistake here breaks every bookmark and every permalink already copied by users, silently and permanently.
  - Hand-rolled search ranking will occasionally rank surprisingly. Keep `scoreRec` as one ~50-line pure function with weights in a `W` literal, and make the empty-query state show recents so the common case never depends on scoring at all.
  - Index build cost on a multi-MB spec. Build lazily via `requestIdleCallback`, cap property harvesting at 40 props / depth 3 per schema, and never build it on the load critical path.
  - Namespacing `apex-env` resets existing users' server choice once, and `pruneStorage()` can drop expansion state a user expected to persist. Read the old `apex-env` key as a one-line fallback; use LRU with a 60-key window; every read already degrades to a default.
  - Loud upgrade breakage: a Symfony app still setting `ui.default` hard-fails container compilation (the `ui` node is not `ignoreExtraKeys`), and dropping the promoted `Config::$defaultUi`/`$showUiSwitcher` shifts positional constructor arguments for anyone constructing `Config` positionally — the latter fails at runtime with a wrong-typed value, not at compile time. Both need explicit UPGRADING.md entries; consider a deprecation shim that accepts and ignores `ui.default` for one minor version.
  - The CDN deletion and the layout rewrite land in the same change, producing a large hard-to-bisect diff. Mitigated by WS1 splitting `css()`/`js()` into part-methods FIRST (so WS2–WS7 are separately reviewable and revertable) and by not touching `renderSchema`'s recursion structure, `genCode` or `buildExample`, which reviewers can then diff to near zero.
  - Skeletons that do not match the eventual layout cause a visible jump on swap — arguably worse than a spinner. Dimension `.ax-skel` rows to the exact `min-height` of `.axi` and reserve the doc title height.
  - Every `md()` addition (tables, ordered lists, blockquotes) is a change to the ONLY sanitizer between spec-authored text and innerHTML. Table cells must be built from already-escaped text and the escape-first ordering must not be reordered; add a UiRendererSafetyTest case per construct. Note the audits misdiagnosed the fence sentinel (it is NUL-delimited, not space-delimited) — do not 'fix' a bug that does not exist and thereby introduce one.
  - What remains unfixed after this pass and will be the most-felt gap: the schema tree still caps depth (at 4 instead of 3), still shows no example when the spec author wrote none, still does not merge `allOf` or support `discriminator`, and try-it still cannot do multipart, form-urlencoded, cookies or spec-driven auth. Sequence those immediately after and say so in the changelog, so reviewers understand the schema renderer was intentionally left diffable to near zero.
